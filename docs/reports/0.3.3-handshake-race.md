## 2. Cause (confirmed from code at d776efc)

On a real device, the unprivileged app intermittently showed "Armada needs root" on some launches and "Daemon not reachable / IOException" on others while the root daemon was running.

Inspection of the code at `d776efc` explains the race condition:

1. In `daemon/src/main/kotlin/app/armada/daemon/Session.kt` (lines 53–68):
```kotlin
    private fun performHandshake(): Boolean {
        // On connect, the daemon sends {"type":"hello","v":1} first.
        try {
            send(Message.Hello(Protocol.VERSION))
        } catch (e: Exception) {
            return false
        }

        // If the peer is not root, send the denied handshake error and close, before any other frame is read.
        if (!peerIsRoot) {
            try {
                send(Message.Failure(id = Protocol.HANDSHAKE_ID, code = Protocol.DENIED, message = "peer is not root"))
            } catch (ignored: Exception) {
            }
            return false
        }
```
And in `daemon/src/main/kotlin/app/armada/daemon/Server.kt` (lines 72–78):
```kotlin
            val session = Session(reader, writer, peerIsRoot, tools)
            session.run()
        } catch (ignored: Exception) {
        } finally {
            try {
                socket.close()
            } catch (ignored: Exception) {
            }
        }
```
For a non-root peer, `Session.performHandshake` wrote a `hello` frame and then immediately wrote the `denied` error frame, returning `false`. `Session.run()` finished, and `Server.handleClient`'s finally block immediately called `socket.close()`.

2. Meanwhile, in `app/src/main/kotlin/app/armada/DaemonClassifier.kt` (lines 20–53):
```kotlin
            val firstLine = reader.readFrame()
                ?: return DaemonStatus.Unreachable("EOFException")
            val firstMsg = try {
                Messages.decode(firstLine)
            } catch (e: Exception) {
                return DaemonStatus.Unreachable(e.javaClass.simpleName)
            }
...
            // Send Hello back
            try {
                writer.writeFrame(Messages.encode(Message.Hello(Protocol.VERSION)))
            } catch (e: Exception) {
                return DaemonStatus.Unreachable(e.javaClass.simpleName)
            }
```
The app read the first line (`hello`). Then, before reading the next line, it called `writer.writeFrame` to reply with its own `hello`. If the server had already closed the socket, the write threw `IOException` ("Broken pipe"). The classifier caught this at line 51 and returned `DaemonStatus.Unreachable("IOException")` without reading the `denied` error frame that was already in the receive buffer.
If the write completed before the socket close took effect, the classifier proceeded to read the buffered `denied` frame and returned `DaemonStatus.Denied`.

3. In `MainActivity.kt`, `queryDaemonStatus` received `DaemonStatus.Unreachable("IOException")` directly from `classifyStreams` rather than catching an exception, so `MainActivity`'s exception logger was bypassed and the UI displayed "Daemon not reachable / IOException".
