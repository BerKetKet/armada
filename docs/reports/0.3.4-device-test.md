## 4. Deviations

1. **Initially-running daemon found and killed:**
   Upon initial inspection for Step 3, daemon PID 10288 was found already running on the device from an earlier session. Its socket behavior was probed (returning `{"v":1}` to root and `denied` to non-root), and then it was terminated using `su -c 'pkill -f app.armada.daemon.Main'` to ensure the test was executed against a cleanly and freshly spawned daemon instance (PID 16040).
2. **Exploratory 15-iteration loop prior to fresh restart:**
   An initial exploratory 15-iteration loop (`scratch/run_loop.py`) was executed against the existing daemon instance (PID 10288) immediately following root revocation. While all 15 iterations logged `status=Denied` in logcat with zero `IOException`s, iterations 4–6 captured XML from other background applications (`nexuslauncher`, `magisk`, `modemkit`) because `am start` was issued while the device was still processing foreground transitions from Magisk. The full acceptance test was subsequently rerun against the fresh daemon (PID 16040) after UI settling, producing 15/15 clean dumps.
3. **Three-iteration debug loops:**
   Before launching the final 15-iteration acceptance test against PID 16040, a 3-iteration debug loop was run to verify that `am force-stop` followed by a 2-second sleep and `am start` with a 5-second sleep reliably settled into the Armada UI and captured `Armada needs root` in every iteration.
4. **Background-task timeout and timer scheduling:**
   When launching the 3-iteration debug verification, `WaitMsBeforeAsync` was set to 25000ms (exceeding the tool's 10000ms synchronous limit), causing the command to run asynchronously in the background as task-1512. A one-shot timer (task-1516) was briefly scheduled and then cancelled once task-1512 finished.
5. **Brief committed together with report:**
   `docs/briefs/0.3.4-device-test.md` was left untracked during execution and committed together with `docs/reports/0.3.4-device-test.md` in commit `6050325`, rather than being committed as a separate initial commit prior to other changes.
6. **Push instruction override:**
   Per Brief 0.3.4 Step 8 ("Commit the report as a single commit. Push it only after Gash confirms the results with the reviewer."), the report commit was held locally until explicit confirmation was received from Gash and the reviewer.

---

## 5. Open questions

1. **Daemon PID file cleanup on SIGTERM:**
   When the daemon is killed with `pkill` (SIGTERM), `/data/local/tmp/armada/daemon.pid` remains until the next daemon startup, because JVM shutdown hooks may not always delete the file on immediate signal termination. However, `Main.isLiveDaemonRunning()` tests live socket connectivity rather than relying on PID file existence, so stale PID files do not hinder daemon restarts.
