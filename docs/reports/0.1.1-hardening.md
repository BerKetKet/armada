## 3. D8 Synthetic Classes Analysis

Inspection of the generated `app-debug.apk` revealed 7 DEX files:
- `classes.dex`: Kotlin runtime and annotations (970 `kotlin` regular, 108 `kotlin` synthetic, 25 `org/intellij/lang/annotations`, 7 `org/jetbrains/annotations`).
- `classes2.dex` through `classes6.dex`: application classes under `app/armada`.
- `classes7.dex`: 457 synthetic platform classes generated by AGP's D8 dexer.

### Breakdown of classes in `classes7.dex`
- `android/*`: 449 synthetic classes (e.g., `android/app/NotificationChannel`, `android/view/WindowInsetsAnimation`, platform stubs).
- `dalvik/*`: 3 synthetic classes (`dalvik/annotation/optimization/CriticalNative`, `dalvik/annotation/optimization/FastNative`, `dalvik/system/ZipPathValidator$Callback`).
- `com/android/tools/r8/*`: 5 synthetic classes (`DesugarMethodHandlesLookup`, `DesugarVarHandle$0`, `DesugarVarHandle`, `RecordTag`, `annotations/LambdaMethod`).

### Why they are present
AGP 9.4 with `compileSdk 35` and `minSdk 29` enables D8 API modeling by default (`:app:generateDebugGlobalSynthetics`). D8 generates synthetic class definitions for platform APIs introduced across API levels 29 to 35 so bytecode referencing modern Android APIs passes dalvik/art verification safely on earlier Android releases. Every single generated stub is marked with the `SYNTHETIC` access flag (e.g. `0x1601`, `0x1011`, `0x1401`).

### Exemption Rule in `scripts/check-deps.sh`
The scanner matches each class against `scripts/allowed-packages.txt`. If unlisted, it permits the class only if it satisfies both criteria:
```bash
if [[ "$flags" =~ SYNTHETIC ]] && [[ "$class_desc" =~ ^(android|dalvik|com/android/tools/r8)/ ]]; then
    continue
fi
```
Because third-party dependencies (such as AndroidX) contain regular non-synthetic classes under their respective packages, this exemption rule does not permit any external library.
