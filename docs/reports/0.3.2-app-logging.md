### Does the status check run again after rotation?
Yes. `MainActivity` in `app/src/main/AndroidManifest.xml` (lines 8–15) does not declare `android:configChanges`. Thus, screen orientation changes cause Android to recreate the activity, invoking `onStart()` on the new activity instance.

### Is the socket closed on every path before the next check?
Yes. In `queryDaemonStatus()` in `app/src/main/kotlin/app/armada/MainActivity.kt`, `val socket = LocalSocket()` is function-scoped:
```kotlin

80:            socket.soTimeout = 1000

82:            socket.close()
83:            s

85:            android.util.Log.e(TAG, "daemon connect failed", e)
86:            try { socket.close() } catch (ignored: Exception) {}
87:            DaemonStatus.Unreachable(e.javaClass.simpleName)

95:        android.util.Log.i(TAG, statusLine)

98:    }
```
- On the success path: `socket.close()` is called at line 82 prior to returning the status.
- On any exception during connect, stream access, or classification: `catch (e: Throwable)` at line 84 executes `try { socket.close() } catch (ignored: Exception) {}` at line 86.
- No socket is stored in activity member fields or reused across checks.
- Therefore, no socket leak occurs and no fix commit ("app: close status socket on every path") was required.
