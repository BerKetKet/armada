**Observation on read-back:**
The process is gone and the listening socket was immediately released by the Linux kernel. However, `daemon.pid` was not deleted and no shutdown record was appended to `daemon.log`.
Inspection of `/proc/<pid>/status` under Android 15 ART explains this behavior:
`SigCgt: 0000006e400084f8` — bit 15 (`SIGTERM`) is 0. Android ART `app_process` does not register a userspace signal handler for `SIGTERM`. When `pkill` delivers `SIGTERM`, the Linux kernel applies default action `SIG_DFL` (immediate termination), bypassing userspace Java `Runtime.addShutdownHook` threads. This finding was documented in `docs/daemon.md` Section 4.5 and is detailed under Deviations below.

In the original 0.3 implementation, the daemon sent a `hello` frame followed immediately by a `denied` error frame to non-root peers. ## 5. Deviations from Brief

1. **Android ART Signal Disposition on Physical Device:**
   Task A requested verification of graceful shutdown on SIGTERM:
   - "Verification is by reading state back, not exit codes alone:
     - pid file absent after shutdown
     - process gone (ps)
     - socket no longer listening
     - shutdown record present in daemon.log"
   On the Pixel 2 XL reference device running Android 15, `app_process` does not register a userspace signal handler for `SIGTERM` (signal 15; `SigCgt` bit 15 is 0 in `/proc/<pid>/status`). As observed and recorded during device verification, sending `pkill -f app.armada.daemon.Main` causes immediate kernel-level termination (`SIG_DFL`). Consequently:
   - The process is terminated (`PROCESS_GONE`) and the abstract socket is closed by the kernel.
   - However, userspace Java shutdown hooks (`Runtime.addShutdownHook`) and `try-finally` blocks do not run under `app_process` on raw SIGTERM.
   - Therefore, `daemon.pid` was not deleted and `daemon.log` was not appended on device under raw SIGTERM.
   This was thoroughly documented in `docs/daemon.md` Section 4.5.
2. **Unit Test Coverage Scope:**
   As allowed by the brief ("state in the report what could not be unit tested and why"), `LocalServerSocket` operating system signal reception cannot be unit tested in isolation on the desktop JVM because Android framework sockets and ART signal disposition are device-specific. Comprehensive unit tests were written in `:daemon` for `DaemonLifecycle.shutdownExecutor`, timeout handling, and file operations (`DaemonLifecycleTest`).
3. **Commit 1 Scope:**
   Brief file `docs/briefs/0.3.1-shutdown-docs.md` was tracked and committed in Commit 1 (`6fa81af`) alongside the shutdown implementation, as requested by the brief.

## 6. Open Questions

1. **In-Band Daemon Shutdown Command:**
   Because Android ART does not invoke userspace signal handlers for SIGTERM in `app_process`, a future milestone should consider an administrative in-band shutdown request over the abstract socket (e.g. `{"type":"request","tool":"system.shutdown"}` or CLI command `armada shutdown`) or a lightweight native C helper that catches SIGTERM and invokes the clean shutdown sequence.
2. **Abstract Socket Namespace Visibility Across Network Namespaces:**
   Abstract sockets (`armada.daemon`) are scoped to the Linux network namespace. When tools or VPN configurations create isolated network namespaces, the daemon socket may become unreachable from those namespaces.
