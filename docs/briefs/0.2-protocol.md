## Part B: wire protocol and JSON codec in :proto

Everything in :proto is pure Kotlin on the standard library plus java.io. No Android APIs, no reflection, no other libraries. Package app.armada.proto, one concern per file: Json.kt (value types), JsonParser.kt, JsonWriter.kt, Messages.kt, Framing.kt, Errors.kt, Protocol.kt.

B1. JDK API guard. :proto runs on Android, so it may only use JDK APIs that exist on Android API 29. Make the compiler enforce this for :proto, for example with the Kotlin compiler option -Xjdk-release set to the lowest value the Kotlin version supports (verify the option and its value in the official Kotlin documentation, and tell me if it is unavailable). Prove it: add a deliberate use of a newer JDK API (for example removeLast() on a java.util.ArrayList or List.of(...)), show the compile failure, then revert. Do this step first, before the codec.

B2. JSON value types and parser. Types: JsonNull, JsonBool, JsonNumber (holds a Long or a Double), JsonString, JsonArray, JsonObject (keeps insertion order). The parser follows RFC 8259 strictly:
- The input must be exactly one value plus optional whitespace. Trailing data is an error.
- Duplicate object keys are an error.
- Raw control characters below U+0020 inside strings are an error.
- All escapes are supported, including \uXXXX and surrogate pairs. Lone surrogates and invalid escapes are errors.
- Numbers: reject leading zeros, "+1", ".5", "1.", hex, and a bare "-". An integer within the Long range becomes a Long. A number with a fraction or exponent becomes a Double. An integer outside the Long range is an error. NaN and Infinity cannot appear on input or be encoded.
- Maximum nesting depth 64. Maximum input size 1 MiB (1,048,576 bytes). The parser must never overflow the stack.
- Every failure is a JsonException carrying the position. No other exception type may ever escape from parsing, including NumberFormatException, IndexOutOfBoundsException and StackOverflowError.

B3. JSON writer. Compact output. Escape quote, backslash, control characters, and U+2028 and U+2029. Other characters are written as-is. The output never contains a raw newline.

B4. Argument helpers on JsonObject for tool arguments: requireString, optString, requireLong and optLong (with optional min and max), optBoolean, requireObject. Each throws ProtocolException with code bad_args and a message naming the field. Keep this small.

B5. Messages. A sealed Message with: Hello(v), Request(id, tool, args), Cancel(id), Progress(id, data), Result(id, data), Failure(id, code, message). Messages.encode(message): String and Messages.decode(line): Message, which throws ProtocolException (code bad_request) on any problem. Protocol.VERSION = 1. Wire format, UTF-8, one JSON object per line:

    client to daemon
    {"type":"hello","v":1}
    {"type":"request","id":"r1","tool":"ping","args":{"host":"1.1.1.1","count":4}}
    {"type":"cancel","id":"r1"}

    daemon to client
    {"type":"hello","v":1}
    {"type":"progress","id":"r1","data":{"seq":1,"rttMs":12.4}}
    {"type":"result","id":"r1","data":{"sent":4,"received":4}}
    {"type":"error","id":"r1","code":"bad_args","message":"count must be 1..100"}

Rules: every message is an object with a string "type". Unknown extra fields are ignored. An unknown type is an error. id is 1 to 64 characters from [A-Za-z0-9._-]. tool is 1 to 64 characters matching [a-z][a-z0-9_.]*. Every request gets exactly one terminal message, result or error. Cancel produces an error with code "cancelled". Progress may arrive any number of times before the terminal message and never after it. Error codes are a closed set defined as constants: bad_request, unknown_tool, bad_args, denied, unsupported, failed, timeout, cancelled, internal. Proto only validates syntax. Rejecting duplicate in-flight ids and handling version mismatch belong to the daemon in 0.3.

B6. Framing, pure java.io. FrameReader(InputStream, maxBytes = 1 MiB) with readFrame(): String?. It returns the next non-blank line, null at clean end of stream, throws FrameTooLongException when a line exceeds the limit (the caller must then close the connection), and throws TruncatedFrameException if the stream ends in the middle of a line. It decodes UTF-8 strictly, so malformed input is an error. It must handle lines split across reads and several lines arriving in one read. FrameWriter(OutputStream) with writeFrame(String): appends "\n", flushes, and rejects a payload containing a raw newline.

B7. Placeholders. Delete ProtoPlaceholder and its test. Update the placeholder classes in :daemon and :cli to reference Protocol.VERSION so the module wiring stays proven.

B8. Tests (JUnit, deterministic, in :proto):
- A conformance table with at least 40 valid and at least 40 invalid JSON documents covering every rule in B2.
- Depth 64 is accepted and depth 65 is rejected. An input of exactly 1 MiB is accepted and one byte more is rejected.
- A round-trip property test: seeded java.util.Random (print the seed on failure), 10,000 random values, encode then decode, results equal.
- A mutation robustness test: seeded, 20,000 mutated valid documents (byte flips, truncation, insertion). Each must either parse or throw JsonException and nothing else. The whole test runs under a 30-second timeout.
- Messages: a round trip for each type, invalid ids, tools and codes, an unknown type, missing fields, wrong field types, and unknown extra fields ignored.
- Framing: a stream that returns one byte per read, several frames per read, blank lines, an oversize line, a truncated line, invalid UTF-8, and the writer rejecting a newline.

B9. docs/protocol.md for a reader who has not seen this brief: wire format, every message with an example, error codes, limits, the exactly-one-terminal-message rule, and rules for changing the protocol. Adding optional fields is compatible. Removing or renaming a field, or changing its meaning, requires bumping the version.
