# Brief 0.3.4 — Device acceptance test: non-root handshake (fix from 0.3.3)

## Context

Brief 0.3.3 fixed a race in the non-root handshake: the daemon previously sent
a hello frame followed by a denied error to non-root peers, and the app's
classifier could fail its hello write (broken pipe) and report
"Daemon not reachable / IOException" instead of "Armada needs root". The fix
makes the classifier continue reading after a failed hello write, the daemon
send only the denied error to non-root peers, and the app ignore stale results
from overlapping lifecycle checks.

All changes are already on master at ded873a. This brief performs the
outstanding device acceptance test. **No code changes are expected.** If the
test fails, stop and report the failure with verbatim logs — do not patch
anything.

## Preconditions

- Repo: ~/projects/armada, branch master, commit ded873a, working tree clean.
- Pixel 2 XL connected via USB with USB debugging authorized.
- Verify with `adb devices` before starting; abort if the device is not listed.

## Steps (scriptable)

1. Build the debug APK:

./gradlew :app:assembleDebug

2. Install it:

adb install -r app/build/outputs/apk/debug/app-debug.apk

3. Determine how the daemon is started in the current codebase (app-spawned via
   su, a shell script, or the CLI). Derive this from the repo's actual source
   and document the command you used and where you found it in the report.
   Ensure the daemon is freshly started so the test exercises the new code.

4. Manual step performed by Gash between your setup and the launch loop:
   Armada's su grant is revoked in the Magisk app's superuser list. Pause here
   and tell Gash to do this and confirm before continuing.

5. Resolve the launcher activity without assuming its class name:

adb shell cmd package resolve-activity --brief io.github.berketket.armada

6. Launch loop — 15 iterations. For each iteration:

- Start the launcher activity with `adb shell am start`.
   - Wait 5 seconds for the status screen to settle.
   - Capture the on-screen text with `uiautomator dump` and pull the XML.
   - Capture `logcat -d -s ArmadaApp` output for that iteration.
   - Force-stop the app with `adb shell am force-stop` and wait 2 seconds
     before the next iteration.

7. Verdict criteria:

- PASS: all 15 iterations show "Armada needs root" in the dumped UI text,
     and no iteration logs "Daemon not reachable" or an IOException during the
     status check.
   - FAIL: any single iteration shows the wrong status or a broken-pipe /
     IOException path. One failure fails the test; do not rerun to get a pass
     without reporting the failure.

8. Report — write docs/reports/0.3.4-device-test.md containing:

- The daemon start command used and where it was found in the repo.
   - Confirmation that the su grant was revoked before the loop (state it as
     Gash's attestation, not your own observation).
   - Per-iteration status text, copied verbatim from the uiautomator dumps.
   - The full logcat excerpt, copied from captured output only.
   - The verdict and any deviations (failed builds, install retries, adb
     hiccups, iterations skipped) listed honestly.

Commit the report as a single commit. Push it only after Gash confirms the
   results with the reviewer.
