Part 1: :proto protocol updates (documentation and one constant only)
- In docs/protocol.md add section 7 "Handshake and connection errors":
  - On connect, the daemon sends {"type":"hello","v":1} first.
  - The client must reply with a hello whose v equals Protocol.VERSION. Otherwise the daemon closes the connection.
  - A connection-level error uses id "handshake", so it fits the Failure shape: {"type":"error","id":"handshake","code":"denied","message":"..."}. The daemon sends it and closes the connection. Codes used this way are denied and bad_request only.
  - Duplicate in-flight id: the daemon answers the second request with {"type":"error","id":"<that id>","code":"bad_request","message":"duplicate in-flight id"} and leaves the first request running.
- Commit: "docs: protocol handshake, connection errors, duplicate ids"

Part 2: dispatch logic in :daemon (pure JVM, no android imports)
- Package app.armada.daemon. Files: Dispatcher.kt, Tool.kt, EchoTool.kt, Session.kt.
- Tool interface: name, and run(args: JsonObject, ctx: ToolContext): JsonObject, where ToolContext offers progress(data: JsonObject) and a cancellation check. A tool that is cancelled must stop promptly.
- EchoTool: tool name "echo". Args: text (required string, max 4096 chars, else bad_args) and delayMs (optional long, 0..10000, default 0, else bad_args). It waits delayMs, checking for cancellation every 10 ms, then returns {"text": <text>}. If delayMs is greater than 0, it sends one progress message {"seq":1,"elapsedMs":<n>} before returning.
- Session(reader: FrameReader, writer: FrameWriter, peerIsRoot: Boolean, tools: Map<String, Tool>): it runs the handshake, then reads frames in a loop.
  - Writes are serialised with a lock, because requests run on worker threads.
  - Every request produces exactly one terminal message: result or error. This is enforced by one guarded terminal-state flag per request id.
  - Progress is never written after the terminal message for that id.
  - cancel for an in-flight id: the tool is interrupted, and the request ends with error code cancelled. cancel for an id that is not in flight is ignored silently, and the brief says why in the protocol doc.
  - Unknown tool: unknown_tool. Bad args from a tool: bad_args. A malformed frame: bad_request. Frames that fail Messages.decode get an error with id "handshake" only if no id could be read; otherwise they get the id's error. Document the chosen rule in docs/daemon.md.
  - If the peer is not root, send the denied handshake error and close, before any other frame is read.
  - On a FrameTooLongException or a TruncatedFrameException, close the session.
  - Unexpected exceptions inside a tool produce failed with the message text, never a stack trace.
- Tests in :daemon/src/test (JUnit, deterministic, fake streams and a controllable clock where needed):
  - handshake succeeds with matching v
  - handshake closes on a mismatched v
  - non-root peer gets denied on the handshake id, then the stream is closed, and no request is processed
  - echo round trip returns the text
  - echo with delayMs emits one progress message, then one result
  - echo with text longer than 4096 chars returns bad_args
  - echo with delayMs above 10000 returns bad_args
  - unknown tool returns unknown_tool
  - duplicate in-flight id returns bad_request and the original request still completes
  - cancel during a long echo returns cancelled, and no result follows
  - cancel for an id not in flight is ignored
  - exactly one terminal message per request, asserted over a batch of 50 requests with random interleaving (seed printed on failure)
  - no progress after the terminal message
  - malformed frame returns bad_request
- Commit per coherent piece, for example "daemon: dispatcher and session", "daemon: echo tool", "daemon: session tests".

Part 3: socket server and daemon main in :daemon (android allowed here)
- Server.kt: uses android.net.LocalServerSocket bound to the abstract name "armada.daemon". For each accepted LocalSocket, read the peer credentials with getPeerCredentials() and compare uid with 0. Pass peerIsRoot to Session. Run each session on its own thread. Close sockets on exit.
- Main.kt: app.armada.daemon.Main with a main(args) that starts the server and blocks. It refuses to start if its effective uid is not 0 (check via android.system.Os.getuid() or the framework equivalent; document which). It writes a pid file to /data/local/tmp/armada/daemon.pid and refuses to start if another live daemon holds the socket. The pid file is cleaned up on normal exit.
- Probe, do not assume: if LocalSocket.getPeerCredentials() is unavailable or fails at minSdk 29, stop and report it. Do not fall back to anything else.
- Unit tests for the pid file and root check logic where they can be isolated. Socket behaviour is verified on the device by the human, not in CI.
- Commit: "daemon: local socket server and main"

Part 4: CLI in :cli
- app.armada.cli.Main with main(args). Commands: hello; echo <text> [--delay-ms N]. It connects to the abstract socket "armada.daemon", does the handshake, sends one request, prints the result data as one JSON line to stdout, and exits 0 on result. On error it prints the error JSON to stderr and exits 1. Usage errors exit 2.
- Parse arguments by hand. No argument-parsing library.
- Unit tests for argument parsing and exit-code mapping, with the socket hidden behind an interface so tests use fake streams.
- Commit: "cli: hello and echo commands"

Part 5: root-denied screen in :app
- Replace the stub activity with one framework-views activity. Keep the package app.armada.
- On start, it connects to "armada.daemon" in a background thread and classifies the outcome into one of three states:
  - connected: shows "Daemon running" and the protocol version
  - denied: the handshake returned error code denied. Shows "Armada needs root. This app is not root, so the daemon refused it. Start the daemon with su and use the CLI." It must not offer a retry button that suggests it will succeed.
  - unreachable: the socket connect failed or the handshake got no answer. Shows "Daemon not reachable" with the raw exception class name.
- The states must be distinct in code and in tests (unit-test the classifier with fake streams).
- Set android:exported="false" on the activity unless a reason is written in the report.
- Do not add any permission. Do not request root. Do not run su.
- Commit: "app: status and root-denied screen"
