# Brief 0.1.1: make the guardrails trustworthy

Read GEMINI.md and OUTLINE.md first. Follows brief 0.1. No features: this brief only hardens the checks and the build supply chain.

## Goal

The dependency rule and the build must be enforced by checks that cannot pass by accident. Every check must (a) fail closed: if it cannot do its job, it fails and never passes silently; and (b) be shown failing on a deliberate violation, not only passing on a clean tree.

## Context

The review of 0.1 found:
- The APK scan in scripts/check-deps.sh pipes the dex files through strings and an anchored grep. This is likely to miss class names (dex stores a length byte before each name, and when that byte is printable, strings glues it to the name so the anchored pattern fails). It was never run against an APK that actually contained androidx.
- The text scan of build.gradle.kts only sees string-literal coordinates at the start of a line. It cannot see kotlin("..."), version-catalog aliases, files(...), buildSrc, or transitive dependencies.
- The Gradle wrapper pins no checksum, and Gradle dependency verification is not set up.
- AndroidManifest.xml has the default allowBackup.

This brief authorizes you to restructure scripts/deps-allowlist.txt as described below. Otherwise the rule in GEMINI.md against editing the allowlist applies.

## Do

1. APK scan: replace strings|grep with dexdump from the SDK build-tools. Find sdk.dir in local.properties, else ANDROID_HOME, and pick the newest build-tools directory containing dexdump. If none is found, fail with a clear message. List every class defined in every dex file of the APK, reduce each to its top-level package prefix, and compare with a new file scripts/allowed-packages.txt. Start that file with app/armada and kotlin only. Run the scanner and report every other prefix it finds and which dependency it comes from. The only additions you may make to the file yourself are org/jetbrains/annotations and org/intellij/lang/annotations, and only if they are present and trace back to kotlin-stdlib. Anything else: stop and report, do not add it.

2. Resolved dependency graph: add a check that runs Gradle's dependency report for :app, :daemon and :cli (debugRuntimeClasspath), :proto (runtimeClasspath) and :proto (testRuntimeClasspath), parses every module coordinate including transitive ones, and compares them with scripts/deps-allowlist.txt. Give that file two sections, [runtime] and [test]. Put the stdlib's transitive libraries in [runtime] and JUnit with its transitives in [test], each with its exact observed version and a comment naming what pulls it in. This graph check is the authority. Keep the text scan only as a quick early message. Fail closed if Gradle's output cannot be parsed or yields zero coordinates.

3. Prove the checks with deliberate violations. Revert each afterwards, and show each in the report with the real failing output:
   a. Add implementation("androidx.core:core:1.13.1") to :app, build the APK, and show that the APK scan and the graph check both flag it independently of the text scan (run each check separately, or write the declaration in a form the text scan cannot see).
   b. Add junit as an implementation dependency in :proto and show it is rejected.
   After reverting, run a clean build and all checks and show that they pass.

4. Wrapper checksum: add distributionSha256Sum to gradle/wrapper/gradle-wrapper.properties using the checksum Gradle publishes for the exact distribution in use. Download the official .sha256 file from services.gradle.org and state the URL in the report. Show that the wrapper still runs.

5. Dependency verification: generate gradle/verification-metadata.xml with sha256 checksums (./gradlew --write-verification-metadata sha256 with the tasks needed to resolve everything: assembleDebug, :proto:test, and the dependency reports). Show that the build passes with it, and show that it fails when one checksum is deliberately altered, then revert. Add a short "Updating dependencies" paragraph to README.md saying how to regenerate it.

6. Manifest: set android:allowBackup="false" on the application element.

7. Commits: small, one concern each, real messages.

## Don't

- Do not add any dependency. Do not change module structure. Do not add features.
- Do not change applicationId or package names.
- Do not edit OUTLINE.md, GEMINI.md or any brief.
- Do not touch the phone.

## Done when

- scripts/check-deps.sh runs the text scan, the graph check and the APK package scan, and any one failing makes it exit non-zero.
- Each deliberate violation in step 3 was caught, with output shown.
- A clean build and all checks pass after reverting.
- The wrapper checksum and verification-metadata are in place and proven.

Verify: ./gradlew clean assembleDebug :proto:test, then scripts/check-deps.sh.

## Report back

Follow GEMINI.md. In the report include the full lists of packages and dependencies observed in the APK and the graph, the proof outputs, and anything you declined to add to an allowlist. Exclude gradle/verification-metadata.xml from the appendix diff and state its size in lines instead.
