Part 1: hello version overflow
- Problem: Messages.decode converts the "v" field with longValue.toInt(). So {"type":"hello","v":4294967297} is accepted as version 1. Wrong.
- Fix: check the Long range before converting. Reject any v that is less than 1 or greater than Int.MAX_VALUE with ProtocolException(code bad_request). Do not truncate.
- Regression tests in proto/src/test/kotlin/app/armada/proto/MessagesTest.kt:
  - v = 4294967297 is rejected
  - v = 4294967296 is rejected
  - v = 2147483647 is accepted (Int.MAX_VALUE)
  - v = 2147483648 is rejected
  - v = 0 and v = -1 are rejected
  - v = 1 is accepted
- Commit: "proto: reject out-of-range hello version"

Part 2: lone surrogates on the writer
- Problem: JsonWriter.writeString writes a lone UTF-16 surrogate as-is. When the frame is encoded to UTF-8 it becomes '?', so the receiver gets different data. Wrong.
- Fix: JsonWriter.write must reject any string that contains a lone high surrogate (U+D800..U+DBFF not followed by U+DC00..U+DFFF) or a lone low surrogate, by throwing JsonException with a position. Valid surrogate pairs are written as-is.
- Tests in proto/src/test/kotlin/app/armada/proto/JsonConformanceTest.kt or a new JsonWriterTest.kt:
  - a string with a lone high surrogate is rejected
  - a string with a lone low surrogate is rejected
  - a valid pair (U+1F600) is accepted and round-trips
  - the round-trip of a value containing U+2028 and U+2029 keeps them escaped and equal
- Add a line to docs/protocol.md section 1 stating that encoders reject lone surrogates. This is the only change to docs/protocol.md in this brief.
- Commit: "proto: reject lone surrogates in JSON output"
