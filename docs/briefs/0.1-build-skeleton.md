# Brief 0.1: build skeleton

Phase 0, step 1 of 4. Read `GEMINI.md` and `OUTLINE.md` first.

## Goal

A repo that builds a debug APK from empty module stubs with **zero runtime dependencies beyond the Kotlin standard library**, plus a script that enforces that rule. No features. The point is a clean, boring, reproducible base.

## Context

- Repo root: the project directory. Only `OUTLINE.md` and `GEMINI.md` exist so far.
- Later steps (not yours now): 0.2 the message protocol and JSON codec in `proto`, 0.3 the root daemon and CLI talking to each other, 0.4 the capability probe.

## Do

1. **Check the environment first** and report what you find before changing anything: JDK version, Android SDK path, installed platforms and build-tools, whether the NDK is installed, Gradle availability. If something required is missing, stop and report instead of installing things.
2. **Create a Gradle project** using the Gradle wrapper, Kotlin DSL, versions pinned. Use compileSdk 35, targetSdk 35, minSdk 29. Package prefix `app.armada`.
3. **Modules, all as empty as possible:**
   - `:app` — Android application. One activity showing the text "Armada" and nothing else. No layouts beyond what is needed, no themes pulled from libraries (use the platform's DeviceDefault theme), no AppCompat.
   - `:proto` — plain Kotlin/JVM library with one placeholder class and one placeholder unit test. It must build and test on the desktop without Android.
   - `:daemon` — Android library, one placeholder class. Later this holds the root daemon.
   - `:cli` — Android library, one placeholder class. Later this holds the command-line client.
   - `:app` depends on `:proto`, `:daemon`, `:cli`. `:daemon` and `:cli` depend on `:proto`.
4. **Dependencies.** Declare only the Kotlin standard library for runtime. JUnit is allowed in `testImplementation` of `:proto` only. Do not add `androidx` anything. Do not enable Compose, view binding or data binding.
5. **`scripts/deps-allowlist.txt`** listing the allowed dependency coordinates (the Kotlin stdlib, JUnit as test-only), one per line.
6. **`scripts/check-deps.sh`** that:
   - scans every `build.gradle.kts` for dependency declarations and fails with a clear message if any coordinate is not in the allowlist,
   - also fails if the built debug APK contains any `androidx` class,
   - prints a one-line OK message when clean.
   Use plain bash plus standard tools only. No Python or other runtime required.
7. **`.gitignore`** for Gradle, Android Studio and IDE files, build output, `local.properties`, keystores.
8. **Minimal README.md** at the root: one paragraph and the three build/test/check commands.
9. **Commits.** Several small commits (wrapper and settings, each module, the check script, gitignore and README), each with a real message.

## Don't

- Do not add any dependency not described above. If the build fails without one, stop and report.
- Do not add features, tools, permissions, networking, or placeholder UI.
- Do not use version catalogs with extra libraries "for later".
- Do not edit `OUTLINE.md`, `GEMINI.md` or this brief.
- Do not touch the phone.

## Done when

- `./gradlew assembleDebug` succeeds.
- `./gradlew :proto:test` passes.
- `scripts/check-deps.sh` prints its OK line.
- Temporarily adding a forbidden dependency line (for example `implementation("androidx.core:core-ktx:1.13.1")`) to a build file makes `scripts/check-deps.sh` fail with a useful message. Revert the change afterwards. Show the failing output in your report.
- The APK contains no `androidx` classes.

## Verify

```
./gradlew assembleDebug
./gradlew :proto:test
scripts/check-deps.sh
unzip -l app/build/outputs/apk/debug/app-debug.apk
git log --oneline
git status --short
```
