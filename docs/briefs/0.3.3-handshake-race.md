# Brief 0.3.3: fix the non-root handshake race

Start: run git fetch and git log --oneline -6 origin/master. Master must include the commit "docs: require one push per code commit" with CI green. No other brief may be in flight. If either is not true, stop and tell the human.

Rules: add commits only, no rebase, no force push. One push per code commit, and wait for CI green on each before the next commit. A batch push is a deviation and goes in the report.

Scope: :app (DaemonClassifier.kt, MainActivity.kt, one new small class, tests), :daemon Session.kt and SessionTest, docs/protocol.md section 7, docs/daemon.md section 3, and the report. Change nothing else. No new dependency, permission or root call.

## Cause (for you to confirm, not assume)

On a device the app, which is not root, shows "Armada needs root" on some opens and "Daemon not reachable / IOException" on others, with the daemon running. The code at d776efc explains it:
- Session.performHandshake, for a non-root peer, sends hello, then the denied error, then returns. Server.handleClient closes the socket right after.
- DaemonClassifier.classifyStreams reads the first frame (hello), then WRITES its own hello before reading the next frame. If the daemon has already closed, that write throws IOException (broken pipe). The classifier catches it and returns Unreachable("IOException") without reading the denied frame that is already buffered. If the write wins the race, it reads denied and returns Denied.
- The 0.3.2 logging in MainActivity does not see this exception, because the classifier catches it first.

## Part 1: the classifier survives a failed hello write

- Change DaemonStatus.Unreachable to data class Unreachable(val exceptionClass: String, val detail: String? = null). Existing call sites and tests must compile and pass unchanged.
- Fill detail with the exception message wherever an Unreachable is created from an exception. For the EOF-before-greeting case use the detail "peer closed before greeting".
- In classifyStreams, when writing the client hello throws: remember the exception and do NOT return yet. Read the next frame. If it decodes to a Failure with code denied, return Denied. Otherwise return Unreachable with the class name and message of the WRITE exception. If the write succeeds, behaviour is unchanged.
- Write these tests first, in DaemonClassifierTest:
  1. Input is a hello frame followed by a denied error frame. The output stream throws IOException("Broken pipe") on every write. Expect Denied.
  2. Input is only a denied error frame. The output stream records bytes. Expect Denied and zero bytes written.
  3. Input is a hello frame then end of stream. The output stream throws IOException("Broken pipe"). Expect Unreachable with exceptionClass IOException and a detail that contains "Broken pipe".
- Run ./gradlew :app:test > red.log 2>&1 before you change the classifier. Test 1 must fail on the old code. Keep red.log for the report. Then implement, run again, keep green.log. If test 1 does NOT fail on the old code, stop and report that, because my diagnosis would be wrong.
- Commit tests and fix together: "app: classifier keeps reading after hello write failure". Push. Wait for CI green.

## Part 2: the daemon sends only the denied error to non-root peers

- In Session.performHandshake, for a non-root peer send ONLY Message.Failure(id = Protocol.HANDSHAKE_ID, code = Protocol.DENIED, message = "peer is not root") and return false. Do not send hello first. Root peers are unchanged: hello first, then wait for the client hello.
- Update SessionTest: a non-root session writes exactly one frame, the denied error with id "handshake", and no hello. Leave the root-peer tests untouched.
- Do not change Server.kt. Do not add a lingering close.
- Commit: "daemon: send only the denied error to non-root peers". Push. Wait for CI green.

## Part 3: stale status checks are ignored

- Add a small class StatusCheckGate in :app: begin(): Int increments an AtomicInteger and returns the new token, isCurrent(token: Int): Boolean compares it with the latest. Add a unit test: after two begin() calls the first token is not current and the second is.
- In MainActivity keep one StatusCheckGate per activity instance. checkDaemonInBackground takes a token with begin(), and the runOnUiThread block calls updateUi only if gate.isCurrent(token) and !isFinishing and !isDestroyed.
- Extend the Log.i status line so an Unreachable status includes the detail: "status=Unreachable exception=IOException detail=<message>".
- In updateUi, show an Unreachable detail as "<exceptionClass>: <detail>" when detail is not null.
- Commit: "app: ignore stale status checks and show exception detail". Push. Wait for CI green.

Change no other line, and in particular do not touch the stray "<code >" in that section: brief 0.3.1 fixes it.
