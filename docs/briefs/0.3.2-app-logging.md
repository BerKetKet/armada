# Brief 0.3.2: Log daemon connection failures in the status screen

Save this file as docs/briefs/0.3.2-app-logging.md and commit it first, before any other change.

Read GEMINI.md first. Follow the CI section and the Honest reports section. Push the code commit and wait for CI green on it before writing the report. Do not force push. Do not rebase. Add commits only.

Scope: :app MainActivity.kt and DaemonClassifier.kt, their tests, and docs/reports/0.3.2-app-logging.md. Change nothing else. Do not add a permission, a dependency, or any root call.

Problem
- On a real device, rotating the screen from portrait to landscape shows "Daemon not reachable" with IOException, while the daemon is running and answers the root CLI. The app discards the exception message and stack trace, so the cause is not visible.

Part 1: log the real exception
- In MainActivity.queryDaemonStatus, when connect or classification throws, log the throwable with android.util.Log.e, tag "ArmadaApp", message "daemon connect failed", passing the throwable so the stack trace is included.
- Keep the DaemonStatus.Unreachable class name as it is now. Do not change what the user sees.
- Log the status outcome with Log.i, tag "ArmadaApp", as one line, for example: "status=Connected version=1" or "status=Denied" or "status=Unreachable exception=IOException".
- Commit: "app: log daemon connection failures with stack trace"

Part 2: check the rotation path
- Find out whether the status check runs again after rotation. The activity is recreated on rotation by default, so onStart runs again. Confirm this in the code and record it in the report.
- Check that the socket from one check is always closed before the next check starts, including when the first check throws. Record the result.
- Make no behaviour change in this part unless the check shows the socket is leaked or reused. If it is, fix it, add a test, and record the reason.
- Commit only if a fix was needed: "app: close status socket on every path".

Part 3: unit test the logging path
- Keep the classifier pure. Do not add logging to DaemonClassifier.
- Add a test that a classifier failure carries the exception class name into DaemonStatus.Unreachable, using a stream that throws IOException on read.
- Run ./gradlew :app:test --rerun-tasks and capture the output to a file. Paste the per-class counts from app/build/test-results/test.
- Commit: "app: test unreachable classification on stream failure"

Part 4: commit, CI, report
- After the code commits, push. Wait for CI green on each code commit with gh run view.
- Write docs/reports/0.3.2-app-logging.md with:
  - the commit list with SHAs and CI run URLs and conclusions
  - the code paths found in Part 2, quoted from the source with file and line
  - the test counts from the captured output
  - a Deviations section
- Commit the report. Push. Wait for CI green on the report commit.
- Print ONE line: the commit-pinned raw URL of docs/reports/0.3.2-app-logging.md.

Device steps for the human (not run by the agent)
1. Build and install: ./gradlew :app:assembleDebug, then adb install -r app/build/outputs/apk/debug/app-debug.apk
2. Clear the log: adb logcat -c
3. Open the app in portrait. Note the screen text.
4. Rotate to landscape. Note the screen text.
5. Run: adb logcat -d -s 'ArmadaApp:*' 'AndroidRuntime:E'
6. Paste the full output into the report under "Device result".
Do not run these steps as the agent.

Don't
- Do not add any dependency, permission, or root call.
- Do not change the daemon, the CLI, or :proto.
- Do not weaken a check or mark a test @Ignore.

Report back
Follow GEMINI.md. Include the code paths from Part 2 with file and line, the test counts, the commit list with CI runs, and the device steps marked as not yet run.
