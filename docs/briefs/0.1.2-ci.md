# Brief 0.1.2: CI as the independent judge

Read GEMINI.md and OUTLINE.md first. Follows brief 0.1.1. No app features: this brief makes the checks portable and complete, and makes a clean GitHub runner enforce them.

## Context

The review of 0.1.1 found:
- The checks only run on this machine, written and judged by the same agent. A clean runner will expose assumptions about local state.
- scripts/check-deps.sh uses a gawk-only construct (the three-argument match). On Debian and Ubuntu, awk is mawk, so the APK scan would find zero classes and fail with a confusing message.
- The graph check covers only debug classpaths, and the text scan only matches configurations named exactly implementation, api and so on. A releaseImplementation dependency, or any variant-specific one, would pass every check until a release build exists.

## Do

1. Portability: rewrite every awk program in scripts/check-deps.sh (the APK scan and the graph parser) in POSIX awk only, with no gawk extensions. Check this with `gawk --posix` on this machine. Do not install mawk or change the system. Output on a clean tree must be unchanged, and the earlier violation proofs must still behave. The CI run on Ubuntu is the real portability test.

2. Release coverage: add the graph check for :app, :daemon and :cli on releaseRuntimeClasspath. Generalize the text scan to any configuration whose name ends in Implementation, Api, CompileOnly or RuntimeOnly (including variant-prefixed ones such as releaseImplementation and debugImplementation) and to add("...", "...") calls with a literal string coordinate. Proof: add the line add("releaseImplementation", "androidx.core:core:1.13.1") to :app and show that the graph check rejects it. The debug APK does not contain it, so this proves the release coverage. Use --dependency-verification=lenient only if you must, and say so. Revert afterwards.

3. CI workflow at .github/workflows/ci.yml. Triggers: push to any branch, and pull_request. Top-level permissions: contents read only. One job on ubuntu-latest: check out the code, set up JDK 21, make sure the Android platform and build-tools the project needs are present (use the runner's preinstalled SDK through ANDROID_HOME, and install anything missing with sdkmanager from the SDK itself, not a third-party action), then run ./gradlew clean assembleDebug :proto:test and scripts/check-deps.sh. Third-party actions: only actions/checkout and actions/setup-java, each pinned to a full commit SHA with the tag in a comment, taken from a release at least two weeks old. Look the SHAs up with gh api, and state in the report exactly how you verified each. No secrets, no caching actions, no other actions.

4. Prove CI is a gate: create a throwaway branch named ci-proof, commit a deliberate violation (the same hidden androidx dependency in :app), push the branch, and show with gh run list, gh run watch and gh run view --log-failed that CI fails on that branch for the right reason. Then delete the branch locally and on the remote. The violation must never reach master.

5. Show CI green on master: push the code commits to master and watch the run to the end with gh run watch. Show the final status and the run URL. If it is red, find and fix the cause and repeat. Never weaken a check to get green. Any fix needed because the runner differs from this machine goes in its own commit with the reason in the message.

6. GEMINI.md: you are authorized to append exactly one section, titled "CI", with this text: "After pushing code commits, wait for CI on that commit with gh run watch. A task is not done while CI is red: fix the cause, and never weaken a check to get green. Only then write the report, including the CI run URL and its final conclusion, commit it, and push it. This changes the order in the Publishing and reports section: code is pushed and CI is green before the report is written." Apply the append and commit it as its own commit. Do not edit anything else in GEMINI.md.

7. Commits: small, one concern each, real messages, per GEMINI.md's "Work in small committed steps".

## Don't

- Do not add any GitHub Action beyond the two named, and do not add secrets.
- Do not weaken, skip or loosen any check to make CI pass.
- Do not edit OUTLINE.md or any brief. GEMINI.md only as authorized in step 6.
- Do not touch the phone.

## Done when

- check-deps.sh uses POSIX awk only, covers release classpaths, and rejects variant-prefixed declarations.
- The release proof is shown, and reverted.
- The ci-proof branch failed CI for the right reason and no longer exists anywhere.
- CI is green on master, with the run URL shown.
- The GEMINI.md CI section is appended.
